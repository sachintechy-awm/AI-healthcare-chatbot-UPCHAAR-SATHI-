# UPCHAR SATHI 🌿 — AI Healthcare Chatbot

UPCHAR SATHI ("treatment companion") is a Django web app that lets anyone
describe their symptoms in plain language and get back:

- 🩺 Possible causes
- 💊 General medicine category guidance
- 🌿 Home remedies
- 🚩 Red-flag warning signs — when to see a doctor
- ⚠️ A safety disclaimer

Responses are generated by **Google's Gemini API**, guided by a system
prompt that keeps answers general, non-prescriptive (no exact dosages or
brand names), and always points the user toward professional care when
needed.

> ⚠️ **This is a demo/learning project, not a medical device.** It must not
> be used as a substitute for professional diagnosis or treatment. See the
> "Responsible use" section below before deploying it for real users.

---

## Features

- **Accounts** — sign up, log in, log out (Django's built-in auth)
- **Saved conversation history per user** — a sidebar lists all your past
  chats by title/date; click one to reopen it, or delete it
- **Ambient animated background** — soft drifting blurred color blobs behind
  a frosted-glass chat panel, on both the chat screen and the login/signup
  screens
- **Dark mode toggle** — remembered via `localStorage`, one click in the header
- **Copy-to-clipboard** on every bot reply
- Clean, warm, mobile-responsive chat UI (vanilla HTML/CSS/JS, no build step)
- Django backend with a small REST-ish API (`/api/send/`, `/api/new/`, `/api/session/<id>/delete/`)
- Gemini API integration via simple REST calls (`requests`), no extra SDK
- Quick-start "symptom chips" for common complaints
- Clear in-app medical disclaimer, shown on every screen

## 1. Setup

### Prerequisites
- Python 3.10+
- A free Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey)

### Install

```bash
# from the project root
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

### Configure your API key

```bash
cp .env.example .env
```

Open `.env` and paste your key:

```
GEMINI_API_KEY=your_real_key_here
```

### Run migrations and start the server

```bash
python manage.py migrate
python manage.py runserver
```

Visit **http://127.0.0.1:8000/** and start chatting.

## 3. How it works

1. You sign up / log in (`/signup/`, `/login/`) — every page except those
   requires authentication (`@login_required`).
2. The browser posts the user's message + current `session_id` to
   `POST /api/send/`.
3. `views.send_message` saves it to that user's `ChatSession`, pulls the
   last few turns for context, and calls `gemini_service.ask_gemini(...)`.
4. `ask_gemini` sends the conversation + a fixed **system prompt** to the
   Gemini `generateContent` endpoint. The prompt forces a structured,
   cautious reply and forbids specific dosages/brand names.
5. The reply is saved and returned as JSON; the frontend renders it as a
   chat bubble and updates the sidebar history list.
6. "Start a fresh chat" calls `POST /api/new/` to create a new session;
   clicking the trash icon on a sidebar item calls
   `POST /api/session/<id>/delete/`.

## 4. Customizing

- **Change the model**: set `GEMINI_MODEL` in `.env` (e.g. `gemini-2.5-pro`).
- **Change the tone/structure of replies**: edit `SYSTEM_PROMPT` in
  `chatbot/gemini_service.py`.
- **Change the look**: colors, type and spacing are all defined as CSS
  variables at the top of `static/css/style.css`.
- **Persist chat across devices**: currently history is tied to the Django
  session cookie; add real user accounts (`django.contrib.auth`) if you
  want login-based history.

## 5. Responsible use — please read

This project is built for learning/demo purposes. Before using it with
real patients or the public:

- Add a visible **Terms of Use** and **Privacy Policy**; explain what
  happens to the symptom data users type in.
- Do **not** let the model output be treated as a diagnosis — keep the
  "not a substitute for a doctor" disclaimer visible everywhere.
- Consider rate limiting and abuse protection on the `/api/send/` endpoint.
- Consider adding an escalation flow (e.g. a visible emergency-numbers
  banner) for messages that look like emergencies.
- Review applicable regulations in your country for health-advice apps
  (e.g. telemedicine rules) before any real deployment.
- Never commit your real `.env` / API key to version control.

---

## 6. Deployment notes

For production:
- Set `DJANGO_DEBUG=False` and a real `DJANGO_SECRET_KEY`.
- Set `DJANGO_ALLOWED_HOSTS` to your real domain(s).
- Run `python manage.py collectstatic` and serve `/static/` via your web
  server or a CDN.
- Put the app behind HTTPS and a production WSGI/ASGI server (gunicorn,
  uvicorn, etc.), not `runserver`.
